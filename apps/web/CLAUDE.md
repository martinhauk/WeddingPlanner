`@weddingplanner/web` is the public one-pager (Vite + React + TypeScript) plus a separate `/admin`
HTML entry, deployed as static files to Azure Static Web Apps.

## Ground rules

- **Content is baked, not fetched.** The bake (`pnpm content:bake`) writes
  `src/content/generated/` and `public/content/` from an instance directory (default
  `samples/instance`). Both folders are gitignored; never commit them or hand-edit them.
- **Feature flags** come from the baked `build.json` (`features.<name>`). A flag only hides UI; the API
  enforces the same flag on its side. Guest-visible features ship dark. See
  [`docs/conventions/feature-flags.md`](../../docs/conventions/feature-flags.md).
- **No API calls on the home page** except the `GET /api/health` keep-warm ping.
- **`staticwebapp.config.json`** is generated by `swa-config/build-swa-config.ts` only (S0-07).
- **Sections:** a section task touches only `src/sections/<type>/`, its schema file in
  `packages/content`, its own string module and its e2e spec.
- **Admin:** each admin task touches only `src/admin/<area>/`; public pages never import admin code.
- **Languages:** every user-visible string exists in de, en and es.
- **Tests:** Vitest + Testing Library next to the code; Playwright screenshot cases in
  `tests/e2e/` for every UI change (sample content only).
